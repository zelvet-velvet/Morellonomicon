# Data scripts and sources (Morellonomicon)

Python 3 standard library only; run from the repo root with `python3 -I`. `git pull` first: the GitHub job may have regenerated files.

- **Data sources are public and cited.** Riot Data Dragon (`ddragon.leagueoflegends.com`, `zh_TW`) and CommunityDragon (game text, game files, loading screen art shown by address); lanes from Meraki Analytics; character sounds from Unicode's Unihan; Mayhem augment numbers from the League of Legends Wiki (CC BY-SA 3.0, credited on the page; Arena's game data differs for many augments). Every page shows the **patch version** it was generated from. Never invent statistics: win rates and pick rates come from a named source with a date, or are left out.
- **New patch.** A GitHub Actions job (`.github/workflows/update-patch.yml`) runs `tools/update_patch.py` Wed-Fri and commits the result, so `git pull` before editing generated files. By hand: `python3 -I tools/update_patch.py --commit`. Riot's patch notes may be summarised in short (names, numbers, one line) with a link; never copy a notes page wholesale or put Riot's images in the repo (they are shown from Riot's site by address).
- **Riot key.** Never ask the user to paste it into chat and never print or commit it: it lives in `.env` (git-ignored) or `RIOT_API_KEY`, and for Home in the plugin settings (`.obsidian/plugins/morellonomicon/data.json`, git-ignored). `tools/fetch_builds.py` reads it itself. A development key expires after 24 hours.
- **Network use.** Only the fetch scripts touch the network, only to the public endpoints above, and only when the user runs them. One exception: Home's profile (`plugin/src/data/riot.ts`) calls Riot's API from the device, with the user's own key and Riot ID, only for that user's account, when Home is opened after 10 minutes or refreshed; the result stays in the device's local storage, never in a note.

## Scripts
- Python scripts: fetch_data.py (champions, items), fetch_augments.py, fetch_wiki_augments.py (the League of Legends Wiki's English text of every Mayhem augment into `_data/augment-wiki.json`, the reference for the hand-written `effect` lines; a rerun lists the augments whose wiki text changed), fetch_augment_data.py (augment numbers per level, scaling, stat chips and Riot's augment tags into `_data/augment-data.json`; Arena's map30 data, so only augments shared with Arena), spells.py (per-rank numbers), fetch_builds.py (Match-V5 counts; `--mode ranked` counts lanes into `_data/positions.json`), fetch_changes.py (patch-to-patch diffs), fetch_patch_notes.py (Riot's patch notes in short), update_patch.py (runs them all), retag_features.py (re-reads ability tags from the notes offline), fetch_mastery.py (your own champion mastery into the git-ignored `_data/mastery.json`; `--riot-id "Name#TAG"` is used to find the account and never stored; the file holds no name or account id), add_game_text.py (fills the passives' numbers by champion level and the %生命傷害 tag into the notes from the cached game files), vault_paths.py (the note folder names), fetch_item_roles.py (the item shop's class tabs, from the League wiki's item data, into `_data/item-roles.json`), augment_model.py (the augment tiers per champion play style from the champions' own numbers, [[Augment Model]]; hand inputs in `tools/data/augment-model.json` and `tools/data/champion-model.json`), fetch_positions.py (lanes per champion from Meraki Analytics, no key), fetch_loading_tips.py (the Handbook's loading screen tips: the English lines in `tools/data/loading-tips-pick.txt`, matched in the game's English text, shown in Riot's zh_TW; a line not found is listed in `Review/Loading Tip Keys.md`, which exists only then), audit_tags.py (lists the words behind every ability tag in `Review/Tag Audit.md`, to check a rule), check_cards.py (lists the Handbook cards over the Handbook card text limits in [[Layouts]]), list_ui_text.py (the hint texts into `Dev Tools/UI Text.md`), build_sounds.py (how characters are said, from Unicode's Unihan, for the 速查 voice search; rerun only for a new Unicode version), install_plugins.py
- Status helper: `vault_status.py` (the vault commands' mechanical steps; see the `mn-*` command skills).

## Data files
- builds.<mode>.json (fetch_builds.py: counts only, no player names or ids), positions.json (fetch_positions.py, or fetch_builds.py --mode ranked), changes.json (fetch_changes.py), patches.json (fetch_patch_notes.py), augment-text.json (fetch_augment_text.py), augment-data.json (fetch_augment_data.py), augment-wiki.json (fetch_wiki_augments.py, CC BY-SA 3.0), loading-tips.json (fetch_loading_tips.py), sounds.json (build_sounds.py), item-roles.json (fetch_item_roles.py, CC BY-SA 3.0), augment-tiers.json and champion-model.json (augment_model.py)
