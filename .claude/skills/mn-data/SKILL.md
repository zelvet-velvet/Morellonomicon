# Data scripts and sources (Morellonomicon)

Python 3 standard library only; run from the repo root with `python3 -I`. `git pull` first: the GitHub job may have regenerated files.

- **Data sources are public and cited.** Riot Data Dragon (`ddragon.leagueoflegends.com`, `zh_TW`) and CommunityDragon (game text, game files, loading screen art shown by address); lanes from Meraki Analytics; Mayhem games per champion and augment from resg.top (a reference for the augment tiers and item builds only, cached, never committed); character sounds from Unicode's Unihan; Mayhem augment numbers from the League of Legends Wiki (CC BY-SA 3.0, credited on the page; Arena's game data differs for many augments). Every page shows the **patch version** it was generated from. Never invent statistics: win rates and pick rates come from a named source with a date, or are left out.
- **New patch.** A GitHub Actions job (`.github/workflows/update-patch.yml`) runs `tools/update_patch.py` Wed-Fri and commits the result, so `git pull` before editing generated files. By hand: `python3 -I tools/update_patch.py --commit`. Riot's patch notes may be summarised in short (names, numbers, one line) with a link; never copy a notes page wholesale or put Riot's images in the repo (they are shown from Riot's site by address).
- **Riot key.** Never ask the user to paste it into chat and never print or commit it: it lives in `.env` (git-ignored) or `RIOT_API_KEY`, and for Home in the plugin settings (`.obsidian/plugins/morellonomicon/data.json`, git-ignored). `tools/fetch_builds.py` reads it itself. A development key expires after 24 hours. **Home's profile** reads Riot through `plugin/src/data/riotcore.ts`, used both by the plugin with your own key (settings, wins) and by the profile server `server/profile` (a Cloudflare Worker holding the key as the secret `RIOT_API_KEY`, `npx wrangler secret put RIOT_API_KEY`; deploy with `npx wrangler deploy` in that folder, then put its address in `PROFILE_SERVER` in `plugin/src/data/riot.ts`); readers then link with just a Riot ID, the server found by Riot. Readers need Riot's Production key on the Worker; a development or personal key is for testing only.
- **Network use.** Only the fetch scripts touch the network, only to the public endpoints above, and only when the user runs them. One exception: Home's profile (`plugin/src/data/riot.ts`) calls Riot's API from the device, with the user's own key and Riot ID, only for that user's account, when Home is opened after 10 minutes or refreshed; the result stays in the device's local storage, never in a note.

## Scripts
- Python scripts: fetch_data.py (champions, items), fetch_augments.py, fetch_wiki_augments.py (the League of Legends Wiki's English text of every Mayhem augment into `_data/augment-wiki.json`, the reference for the hand-written `effect` lines; a rerun lists the augments whose wiki text changed), fetch_augment_data.py (augment numbers per level, scaling, stat chips and Riot's augment tags into `_data/augment-data.json`; Arena's map30 data, so only augments shared with Arena), spells.py (per-rank numbers), fetch_builds.py (Match-V5 counts; `--mode ranked` counts lanes into `_data/positions.json`; Mayhem mode does not work: tested 2026-11-18 on tw2/sea, kr and na1 (master players and casual players met in ARAM games), Match-V5 lists no queue 2400 games for any player while ARAM 450, Arena 1700/1750 and URF games are there, and ARAM 450 games carry no augments; resg.top's millions of games per patch do not come from this API), fetch_changes.py (patch-to-patch diffs), fetch_patch_notes.py (Riot's patch notes in short; the Mayhem section block by block: new, changed and removed augments, Mayhem champion balance, 主秀英雄; a renamed augment goes in `tools/data/augment-aliases.json`, Riot's name -> the note's name, when the run warns), update_patch.py (runs them all), retag_features.py (re-reads ability tags from the notes offline), fetch_mastery.py (your own champion mastery into the git-ignored `_data/mastery.json`; `--riot-id "Name#TAG"` is used to find the account and never stored; the file holds no name or account id), add_game_text.py (fills the passives' numbers by champion level and the %生命傷害 tag into the notes from the cached game files), vault_paths.py (the note folder names), fetch_item_roles.py (the item shop's class tabs, from the League wiki's item data, into `_data/item-roles.json`), fetch_lcu.py (Mayhem games through the League client running on this PC, the LCU: read-only, a small account, pauses in champion select and games, stops if another account logs in; samples of champion, win, items and augments into the git-ignored offline `.cache/mayhem.sqlite`, no names or player ids; no options opens the full-screen menu and live dashboard (`tools/lcu_tui.py`), `tools/mayhem_crawler.bat` opens it from Windows; it reads a history (~4 s, the client queues them) then opens every unseen game in it (0.23 s, ten samples), one call at a time; `--summary [patch] --export` writes `.cache/lcu/mayhem-stats-<patch>.json`; Riot does not support the LCU, so its numbers are not shown until Zaviel decides), lcu_cache.py (our crawl from `.cache/mayhem.sqlite` written in resg.top's cache format into the git-ignored `.cache/lcu/cache/<patch>/`, adding games of up to two earlier patches for champions, augments and items no patch since changed (changes.json and the patch notes), with thresholds for our volume in its meta.json (`sure_games` 600, `sure_item_games` 1000, `not_offered` from the games per pair) that the tier scripts read, so a patch resg.top has not published can be built from our games; the tier scripts take the newest patch of either source, resg.top when both have it, and never write an older patch over a newer one, so the GitHub job, which has no crawl, leaves a crawl-built patch alone; a skipped step on a machine without the crawl), fetch_resg.py (resg.top's Mayhem games and wins per champion and augment into the git-ignored `.cache/resg/<patch>/`; no licence, so its numbers are never committed or shown), augment_tiers.py (the augment tiers per champion: a reasoning rule per augment from the champion's kit, checked against resg.top's games, [[Augment Model]]; writes `Review/Augment Questions.md` where the two disagree), build_tiers.py (each champion's Mayhem build: a main build of five items and boots plus alternatives per play style, from item kinds and the kit, checked against resg.top's item games, [[Build Model]]; writes `Review/Build Questions.md`), reasoning_todo.py (what the reasoning still needs: augments with no rule, changed augments whose rule was not rechecked, rules for removed augments, trick candidates from `_data/questions.json`, which the two tier scripts write; into `Review/Reasoning Todo.md`, handled items in `tools/data/reasoning-done.json`; `--hook` prints one line for the session start; worked by the skill `mn-reasoning`), fetch_positions.py (lanes per champion from Meraki Analytics, no key), fetch_loading_tips.py (the Handbook's loading screen tips: the English lines in `tools/data/loading-tips-pick.txt`, matched in the game's English text, shown in Riot's zh_TW; a line not found is listed in `Review/Loading Tip Keys.md`, which exists only then), audit_tags.py (lists the words behind every ability tag in `Review/Tag Audit.md`, to check a rule), check_cards.py (lists the Handbook cards over the Handbook card text limits in [[Layouts]]), list_ui_text.py (the hint texts into `Dev Tools/UI Text.md`), build_sounds.py (how characters are said, from Unicode's Unihan, for the 速查 voice search; rerun only for a new Unicode version), install_plugins.py
- Data CLI: `mn.py` (`status`: per patch the lifecycle state, our LCU games with first → last date and game versions, resg.top's count when cached, the snapshots kept; `--json` for a dashboard; `snapshot [--backfill]`: keep `augment-tiers` and `item-builds` per patch, run by update_patch.py; `report`: the PC-only dashboard, `tools/data/report.html` filled with the status, games per day and samples per champion, written to the git-ignored `.cache/reports/status.html` and opened in the browser; never commit or publish it) on `datalib.py` (the shared loader: any data file for any patch, the private counts as counts only). Lifecycle: Announced (the pages are built from it), Archived, Ready (newer, at least `ready_games` of our games, `tools/data/lifecycle.json`, not decided yet), Collecting; design in the folio's `Notes/Data Backend.md`.
- Callout helper: `callouts.py` (sets each callout's type from its boxes in the notes named).

## Data files
- builds.<mode>.json (fetch_builds.py: counts only, no player names or ids), positions.json (fetch_positions.py, or fetch_builds.py --mode ranked), changes.json (fetch_changes.py), patches.json (fetch_patch_notes.py), augment-text.json (fetch_augment_text.py), augment-data.json (fetch_augment_data.py), augment-wiki.json (fetch_wiki_augments.py, CC BY-SA 3.0), loading-tips.json (fetch_loading_tips.py), sounds.json (build_sounds.py), item-roles.json (fetch_item_roles.py, CC BY-SA 3.0), augment-tiers.json (augment_tiers.py), item-builds.json (build_tiers.py), questions.json (augment_tiers.py and build_tiers.py: the pairs where games and reasoning disagree, for reasoning_todo.py), history/<patch>/<name>.json.gz + history/index.json (mn.py snapshot: one gzip copy of augment-tiers and item-builds per patch, the newest run of that patch)
