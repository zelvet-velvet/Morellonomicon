## 🧭 What this is

**Morellonomicon (黑魔禁書)** is a League of Legends guide for beginners, written in **Traditional Chinese (zh_TW)** as an Obsidian vault that opens on a phone. It covers both **Summoner's Rift** (Normal, Ranked: roles, lanes, builds) and **ARAM Mayhem (大混戰)** (which augments fit which champion, strong combos), plus roles, skill damage types and item-pick strategy per mode. Mayhem was built first; Rift is being filled in (the app's Rift mode is still off), so new work should keep both modes in mind.

Base pages (champions, skills, items) are generated by Python scripts from public data; the advice (builds, augment fit, combos) is written and reviewed by people.

## ⚠️ Rules that prevent breakage

- **Language.** Vault content for readers is Traditional Chinese (Taiwan wording; use the official zh_TW client names for champions, items and augments). Workflow notes (this guide, Dev Status, Dev Log, Start Guide) stay English.
- **Folder names.** The note folders (英雄, 道具, 強化, 新手入門, 版本更新) are named in one place for the plugin (the defaults in `plugin/src/settings.ts`) and one for the scripts (`tools/vault_paths.py`); never write a folder name anywhere else. To rename them: change both, `git mv` the folders in one commit, and map the saved `read` paths (they are note paths) to the new ones.
- **Generated vs written.** Generated pages carry `generated: true` in the frontmatter and a marked block; scripts only rewrite inside the marked block, never the hand-written advice around it.
- **Sources and numbers.** Data comes only from public, cited sources (list in skill `mn-data`); every page shows the patch it was generated from. Never invent statistics: win and pick rates come from a named source with a date, or are left out. Only the fetch scripts touch the network, and only when the user runs them (one exception, Home's own Riot profile: skill `mn-data`). A GitHub job regenerates the data Wed-Fri and commits it: `git pull` before editing generated files.
- **Riot key and policy.** Never ask for the key in chat, never print or commit it: it lives in `.env` (git-ignored) or `RIOT_API_KEY` (Home: the plugin settings, git-ignored). Keep Riot's legal line in the README ("not endorsed by Riot Games"). Do not copy another site's tier lists or a patch notes page wholesale; link to them.
- **Nothing private in the repo.** No keys, personal paths or summoner names/IDs of real players.
- **No dependencies in the data scripts.** `tools/` is Python standard library only; no pip installs. The plugin in `plugin/` is TypeScript with npm dev dependencies (esbuild, typescript) for the build only.
- **Plugin.** Source in `plugin/src/`; `cd plugin && npm install && npm run check && npm run build && npm run install-vault` puts `main.js`, `manifest.json`, `styles.css` into `.obsidian/plugins/morellonomicon/`, which **is committed** (the phone cannot build). Rebuild and commit it after every plugin change. Modes live in `plugin/src/modes.ts` (Mayhem now, Rift reserved). UI labels are English, content is zh_TW.
- **Plugins are not in git** (`.obsidian/plugins/` is ignored), except Morellonomicon and **Obsidian Git** (committed so a fresh clone, e.g. on a phone, has it; its `data.json` settings stay per device; update it by replacing its three files with a newer release). `tools/install_plugins.py` downloads the others from each plugin's GitHub release; the list is `community-plugins.json`.
- **Design Rules.** After a new page or a page change, its picture loading is reviewed (the picture check in Design Rules) before committing. How every page looks and behaves (layout, the loading look, the search capsule on the keyboard, controls, words and colour) is in [[Design Rules]] (`Dev Tools/Design Rules/`: the core note for every page plus topic notes); read the core before any UI change, then the topic notes its index lists for what you build, reuse the shared helper it names instead of building a page's own version, and write a new shared behaviour there first. Icons: one idea has one icon everywhere, from the maps in [[Icons]]; a new idea gets its icon in the map and in [[Icons]] first.
- **Layouts first.** A new or changed page layout is proposed in `Dev Tools/Layouts.md` and picked by Zaviel before it is built (skill `mn-layouts`).
- **Testing needs the user's eyes** for Obsidian on a phone and on PC. Say in the chat what could not be tested; do not mark items in notes as "to check on the phone" (Zaviel is the only developer and tests everything).

## 🔁 Workflow


1. Read [[Dev Status]] and the notes or script you are about to change before editing.
2. Make the smallest change that does the job; match the surrounding style.
3. Check it (run the script, open the generated note, read the Chinese text) and say plainly what works, what could not be tested and what you were unsure about. After a new page or any change to a page, also do the **picture check** and the **balance check** in [[Design Rules]] (every picture block has its loading look, what comes next is fetched ahead: the page's `needs` in `plugin/src/pages/index.ts` and Picture readout at `cold 0`, no empty page; no big blank space, weight spread, few components centred) and say what was checked.
4. Record it (see the commands below).
5. **Commit and push every change** to `main` (the regulation is in `AGENTS.md`).

## 📜 Commands: status, journal

The commands (`/cmd-sync`, `/cmd-journal`, `/cmd-rollover`, `/cmd-notes-sync`) are skills; the table is in `AGENTS.md`. The progress lives in **[[Dev Status]]** (🚀 Today (date), 📅 Yesterday (date), ⏳ Ongoing by area, 💡 Ideas), **[[Progress Archive]]** (finished work) and the **day notes** (`Review/Log/…`, one `## ` entry per change; the [[Dev Log]] lists them).

- **Read before edit**: always read a note right before changing it; Zaviel may have rolled something back: never put it back.
- **Trust order** (when sources disagree): the code, then today's chat and Dev Status, then other notes. If a note contradicts the code, say so and suggest `/cmd-notes-sync`.
- **Notifications**: at the very end, only for what changed, one line each: `**[Today's Progress]** Updated in Dev Status`, `**[Journal]** 2 entries in 2026-10-27`. A blank line before and after.

## 🗂️ Vault note format (callouts)


For the workflow notes (`Start/`, `Review/`, `Dev Tools/`) and the inbox templates (`Inbox/`). Not for generated notes (英雄, 道具, 強化), the Handbook decks (`新手入門/`: the app reads their `## ` cards), the day notes' change entries (records with no state), or the long table `tools/audit_tags.py` writes (`Review/Tag Audit.md`). `Dev Tools/UI Text.md` is written by `tools/list_ui_text.py` as one callout per file.

- **Callout before table.** Items that each carry a status or a short detail (tasks, findings, open points, per-area summaries) go in callouts, one per group. A table is only for a real grid read across columns (the Handbook card text limits and stage templates in [[Layouts]], the folder map on [[Home]], the state table below).
- **Callout type = the block's state** (Zaviel, 2026-10-30). A block with a state shows it in its callout type, and the type changes in the same edit as its boxes. The states use the checkbox symbols Minimal draws (its checkbox styles), so a box and its block use the same words:

| Checkbox | Item state | Callout type |
| --- | --- | --- |
| `[ ]` to do · `[/]` incomplete · `[>]` in progress | open or in progress | `[!todo]` |
| `[x]` done | finished | `[!done]` |
| `[!]` important | blocked or waiting for someone (name who or what: Zaviel, a Riot key, the art) | `[!warning]` |
| `[?]` question | waiting for a decision | `[!question]` |
| `[-]` canceled | failed or dropped (say why) | `[!failure]` |
| `[i]` information, or no boxes | no state | `note`, `info`, `abstract`, `example`, `quote`, `tip` |

- **Block from its boxes.** Every box `[x]` (or `[x]` and `[-]`) → `[!done]`; every box `[-]` → `[!failure]`; otherwise any `[!]` → `[!warning]`, else any `[?]` → `[!question]`, else `[!todo]`.
- **Keep it in sync.** Ticking the last open box turns `[!todo]` into `[!done]`; adding an open item to a `[!done]` block turns it back to `[!todo]`. Keep the fold sign (`-` / `+`) and the title.
- **In [[Dev Status]]:** Today and Yesterday are an `[!abstract]` callout under their dated heading (Today open `+`, Yesterday folded `-`); each Ongoing area is one callout titled with the area (its type from its boxes); Ideas is an `[!example]`. Finished work moves to [[Progress Archive]] (`/cmd-notes-sync`). Callout types are set by `python3 -I tools/vault_status.py callouts [note]`, not by hand. An inbox entry is a `[!todo]` callout until it is processed (then it is removed).

## 🗣️ Conventions


- Call the user by the name in `git config user.name`. Reply in the language they write in.
- **Notes:** no `# Title` heading inside a note (Obsidian shows the file name as its title); give workflow notes a `sticker:` lucide icon in the frontmatter. Never write a note named like its folder (make.md's folder notes).
- Champion, item and augment names are linked with `[[ ]]` so the graph and backlinks work (champion ↔ augment ↔ combo).
- Prefer a named constant at the top of a script over a magic number.
